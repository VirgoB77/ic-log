# 売買bot

暗号資産の売買を、決めたルールどおりに自動で繰り返すプログラム。
**過去データで検証してから、紙で試して、それから実弾**という順番で使う。

このフォルダだけで完結している。Node.js があれば動く（追加のインストールは不要）。

## 最初に読むこと

**これは「勝ち方」ではない。同じ判断を繰り返す道具でしかない。**
負ける戦略を載せれば、より速く、より正確に負ける。

- 入っている戦略は、教科書に載っている基本形をそのまま実装したもの。
  これ自体に儲かる仕掛けはない。**まず自分で検証すること。**
- 検証してみると、たいてい「買って持ちっぱなし」に勝てない。
  だから `compare` は必ず持ちっぱなしと並べて出し、負けていればはっきりそう書く。
- 過去データに合わせて設定をいじり回すと、成績はいくらでも良くできる。
  それは**過去に合わせただけ**で、明日には効かない。数字が良すぎたら疑うこと。

## 使い方

### 1. エンジンの検算（まずこれ）

```sh
node bot.mjs selftest
```

売買の計算そのものが正しいかを20項目で確かめる。**ここが通らないうちは他の数字を信じない。**
「未来を覗いていないか」の検査も入っている（バックテストが嘘をつく原因のほぼ全部がこれ）。

### 2. 過去のローソク足を取ってくる

```sh
node bot.mjs fetch --pair btc_jpy --tf 1day --from 2021-01-01
```

bitbank の公開APIから取る。鍵は要らない。`data/` に貯まる（Gitには上げない）。

### 3. 過去データで成績を出す

```sh
node bot.mjs backtest --pair btc_jpy --tf 1day --strategy sma-cross --fast 20 --slow 60
node bot.mjs compare  --pair btc_jpy --tf 1day
```

手数料とすべりを引いた後の数字しか出さない。`compare` は戦略を全部並べて比べる。

### 4. 紙で試す（お金は動かない）

```sh
node bot.mjs paper --pair btc_jpy --tf 1hour --strategy donchian
```

値段は本物、注文は嘘。**最低でも数日は回して**、思ったとおりに動くか見る。

### 5. 実弾

```sh
cp .env.example .env      # 鍵を書く。.env はGitに上がらない
node bot.mjs check        # 鍵が通るか確かめる（残高を読むだけ。発注しない）
node bot.mjs live --pair btc_jpy --tf 1hour --strategy donchian --live --max-order 5000
```

**次の3つが揃わないと1円も動かない。**

1. `--live` を付ける
2. `.env` の `BOT_LIVE_OK` を `yes` にする
3. 起動時に「実弾で回す」と手で打ち込む

うっかり実弾で立ち上がることを防ぐための仕掛けなので、面倒でも省かないこと。

**止めかた**は Ctrl-C か、このフォルダに `STOP` という名前のファイルを置く。
`STOP` を見つけると新しく買うのをやめて降りる。

## 入っている戦略

| 名前 | 中身 |
| --- | --- |
| `sma-cross` | 短い移動平均が長い移動平均を上回っている間だけ持つ。上げ相場に乗る型 |
| `donchian` | 直近N本の高値を終値で抜けたら持つ。安値を割ったら降りる |
| `rsi` | 下がりすぎたら買い、上がりすぎたら売る。横ばい相場向き |
| `buy-hold` | 最初に買って何もしない。**他の戦略はこれに勝てて初めて意味がある** |

## 仕組み

- **判断は「終値」、約定は「次の足の始値」。**
  終値を見た瞬間にその終値で買えることにすると、現実には取れない利益が乗ってしまう。
- **費用は必ず引く。** 手数料は売買のたびに、すべりは自分に不利な側へ倒して計算する。
- **途中の足では判断しない。** 出来上がった足だけを見る。
  まだ動いている足で判断すると、値が動くたびに判断が変わってしまう。
- 現物だけ。買って売るだけで、売りから入る建て方はしない。
  追証もロスカットも無く、**最悪でも買った額しか減らない**ため。

### 安全装置

| 指定 | はたらき |
| --- | --- |
| `--max-order 5000` | 1回の注文はこの額（円）まで |
| `--daily-loss 0.05` | その日の頭から5%減ったら、その日はもう買わない |
| `--max-dd 0.2` | 資産の山から2割減ったら売買を打ち切る |
| `STOP` ファイル | 置くと新規をやめて降りる |

バックテストでも同じ安全装置が効くので、**入れた場合と入れない場合の成績を比べられる。**

## 株や為替でも使う

エンジンは値動きの形しか見ていないので、CSVを渡せば何でも検証できる。

```sh
node bot.mjs backtest --csv 日経平均.csv --strategy sma-cross
```

1行目は見出し、2行目から `日付,始値,高値,安値,終値,出来高` の順。

ただし**自動売買まで通しでできるのは暗号資産だけ**。
株やFXは証券会社ごとにAPIの作りも審査も違うので、そこは繋いでいない。

## 制限

- **取引所の認証API（残高照会・発注）は、作った環境から通信できず、一度も動かして確かめていない。**
  実弾の前に必ず `node bot.mjs check` を通すこと。あれは残高を読むだけの安全な呼び出しで、
  鍵と署名が正しいかをそこで確かめられる。ここが通らなければ発注も通らない。
- **手数料の率は自分で確かめて `--fee` に入れること。** 既定の0.12%は目安でしかなく、
  取引所や板の取り方（Maker / Taker）で変わる。ここを甘く見積もると検証結果が嘘になる。
- **動かし続けるにはパソコンを起動したままにする必要がある。** 閉じれば止まる。
  短い足で回すほど、止まっている間の取りこぼしが効いてくる。
- **利益が出れば税金がかかる。** 日本では暗号資産の利益は原則として雑所得で、
  給与などと合算して課税される。額が大きくなりそうなら先に調べておくこと。
  bot は売買の記録を `state/` に残すので、集計はそこから作れる。
- board（板）を見て指値を置くような細かい注文はしない。成行だけ。
  そのぶん確実に約定するが、すべりは大きくなる。

## ファイル構成

| パス | 中身 |
| --- | --- |
| `bot.mjs` | 入口。コマンドの受け付け |
| `selftest.mjs` | エンジンの検算20項目 |
| `src/engine.mjs` | 売買の実行エンジン（過去データを1本ずつ流す） |
| `src/strategy.mjs` | 売買のルール |
| `src/report.mjs` | 成績の集計と表示 |
| `src/candles.mjs` | ローソク足の取得・CSV読み込み・検算用の作り物データ |
| `src/exchange.mjs` | 取引所とのやり取り（紙／本物） |
| `src/live.mjs` | 時間を進めながら回すループ |
| `.env.example` | 鍵の書き方の見本。`.env` にコピーして使う |

`data/`（足のキャッシュ）、`state/`（持ち高と記録）、`.env`（鍵）は Git に上げない。
**とくに `.env` は絶対にコミットしないこと。** このリポジトリは GitHub Pages で公開されている。
